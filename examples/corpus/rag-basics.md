# RAG 基础

## 什么是 RAG

RAG（Retrieval-Augmented Generation，检索增强生成）是一种把"检索"和"生成"组合起来的方法。系统先从资料库中找出与问题相关的片段，再把这些片段作为上下文交给语言模型，让模型基于片段组织答案。

它解决的核心问题是：语言模型的参数里没有你的私有资料，而且模型可能编造不存在的事实。RAG 不修改模型参数，只在每次回答前动态补充证据，因此资料更新后不需要重新训练。

## 标准流程

一个最小 RAG 系统包含五步：

1. 摄取：读取文档，清洗文本。
2. 分块：把长文档切成适合检索的片段。
3. 索引：用嵌入模型把片段转成向量，写入向量库。
4. 检索：把问题也转成向量，找出最相似的若干片段。
5. 生成：把问题和片段一起交给语言模型，要求它引用片段作答。

每一步都会影响最终质量。分块过粗会稀释语义，过细会丢失上下文；检索召回不足时，再强的生成模型也无法补救。

## RAG 与微调的区别

微调改变模型参数，适合学习风格、格式和领域语感，但难以保证事实准确，资料更新也要重新训练。RAG 把知识放在外部索引里，更新资料只需重建索引，并且可以给出处。

对于个人知识库这类"资料经常变化、必须可追溯"的场景，RAG 更合适。代价是系统多了一条检索链路，延迟和工程复杂度都更高。

## 常见失败模式

- 检索没召回正确片段，模型只能凭空回答。
- 召回了片段，但模型忽略上下文，凭参数记忆作答。
- 引用编号与片段对不上，用户无法核验。
- 资料本身没有答案，模型却给出看似合理的结论。

对应的工程手段是：混合检索提高召回，重排提高精度，提示词约束引用格式，以及设置阈值在证据不足时拒答。
