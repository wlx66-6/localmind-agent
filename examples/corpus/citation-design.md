# 引用设计

## 引用要解决什么问题

RAG 的回答如果没有出处，用户无法判断它是基于资料还是模型臆想。引用把每个结论追溯到具体文档和位置，让回答可核验。

引用不只是"附上文件名"。有用的引用至少要回答：来自哪个文件、哪一节、哪几行，以及原文片段是什么。

## 稳定 ID

每个分块需要一个稳定 ID，用于在数据库、向量库和前端之间关联。常见做法是把文件路径、分块序号和内容哈希拼起来再取哈希。

稳定 ID 的好处是：内容不变时 ID 不变，重建索引不会产生重复；内容变化时 ID 变化，旧向量可以被准确清理。

## 编号与映射

提示词要求模型用 [1]、[2] 这样的编号引用上下文片段。后端在发送上下文前建立编号到分块的映射，生成结束后解析回答中的编号，再换回文件、标题和行号。

这里有两个常见问题：模型引用了不存在的编号，或者回答了事实却没有标注引用。前者可以在解析时过滤，后者只能通过提示词约束和评测统计来改善。

## 行号定位

分块时记录起止行号，前端就能显示"第 15 到 22 行"。相比只显示文件名，行号让用户能快速打开原文核对。

实现上要注意换行符归一化。Windows 的 CRLF 和 Unix 的 LF 会导致行号偏移，解析时应先统一为 LF 再计算。

## 引用与拒答的配合

当检索结果低于阈值时，系统应该拒答，而不是给出没有引用的回答。拒答信息要说明"资料中未找到足够依据"，并提示可以补充什么。

拒答和引用是一体两面：引用保证有依据时能核验，拒答保证没依据时不编造。两者共同构成"可信回答"的边界。
