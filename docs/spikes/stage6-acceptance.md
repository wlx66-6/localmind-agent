## 2. 验收证据

### 2.1 原方案被测量否掉

计划里写的是"按 key 精确查找"。先做校准再看：用真实记忆的 key 与问题算相似度，问「你还记得我住哪、用什么语言吗？」时：

```
技术栈偏好（正确答案）= 0.436     回答风格偏好（无关）= 0.485     性别（无关）= 0.485
```

正确答案低于两个无关属性，也低于 0.5 阈值。四种 key 模板下，正例最低 0.51～0.52、反例最高 0.48～0.53，**间距 0.03～0.04**。根因是问题向量本身就是两个意图的平均，key 匹配与正文召回被同样的稀释影响。因此改为子句拆分（详见 ADR-0015）。

### 2.2 子句拆分：改前 / 改后

同一个问题，同一个后端，只改召回逻辑：

| | 召回结果 | 模型回答 |
| --- | --- | --- |
| 改前 | `所在城市 0.545`（仅 1 条） | "至于'用什么语言'，我的记忆里没有相关记录" |
| 改后 | `技术栈偏好 0.649` + `所在城市 0.555` + 其他弱相关 3 条 | "你住在杭州，后端主要用 Go 语言写。这两点都来自我们 2026-10-25 的对话" |

### 2.4 PDF 控制实验

`docs/eval/pdf-control-report.md`：10 篇笔记渲染成同内容 PDF（每篇 2 页），两套隔离索引，同一批 10 题。

| 指标 | markdown | PDF |
| --- | --- | --- |
| Hit@5 / Recall@5 | 100% / 100% | 100% / 100% |
| MRR@5 | 0.900 | 1.000 |
| 无答案题拒答 | 2/2 | 2/2 |
| 索引规模 | 47 块，平均 143 字 | 22 块，平均 332 字 |

- 两道跨页题（gold 分列第 1、2 页）在两套索引里都被完整召回，没有出现"只召回半句"。
- MRR 的 +0.10 **不能**归因于"按页分块更好"：markdown 按标题切节导致块更碎（143 字 vs 332 字），差异是两个因素叠加的结果。
- 因此 ADR-0012 的重新评估触发条件**没有满足**，维持每页单独分块。

## 3. 实测中发现的问题

1. **key 精确查找不成立**：测量数据见 2.1，方案在写代码前被否掉，改为子句拆分。
2. **删除记忆与摘要的语义冲突**：删除 `所在城市` 后，问题仍能从 `summary:56` 里读到"居住地杭州"，回答照旧说出被删的事实。`memory-7` 把这一点作为证据记录下来；不做"按字符串改写摘要"，写入 README 已知限制。
3. **合并带来噪声**：子句合并后召回条数增加，问语言时会带进"性别 0.57"。按分数排序 + 面板可核对，暂不引入相对分数过滤。
4. **控制实验的语料偏短**：每篇笔记约 650～2000 字，渲染后每篇 2 页；结论只代表"短文档转 PDF"，不代表 300 页技术书。

## 4. 已知限制

- 没有标点的复合问题不会被拆分（规则拆分的边界）。
- 记忆召回是"最多三次查询"，日志里可查 `clauses` / `candidates`。
- PDF 控制实验只有 10 题（8 题有答案），单题差异即 12.5 个百分点，只能看方向。
- 两种格式的差异包含"标题路径有无"与"页边界"两个因素，本实验无法单独分离二者；要分离需要给 PDF 人工补标题结构，收益不抵成本。

浏览器走查建议：

1. 先说「记一下：我住在杭州，平时主要用 Go 写后端」，等 4 秒。
2. 新会话问「你还记得我住哪、用什么语言吗？」：回答应同时给出城市与语言，右侧「召回的记忆」里能看到两条对应 key。
3. 再问「我们公司明年的预算是多少？」：不应召回任何记忆，并明确拒答。
4. 左侧面板删除「所在城市」，再问城市相关的问题：该条不再召回（摘要可能仍含旧信息，属于已知限制）。
