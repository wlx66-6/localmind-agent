# 0005 · 检索策略：混合检索 + Rerank + 阈值拒答

- **状态**：已接受（阶段 2 已用 40 题评测集确定参数，见下方“阶段 2 实测”）
- **日期**：2026-10-24（2026-10-25 更新）
- **决策者**：项目作者 + 协作代理

## 背景

项目要求"回答有依据、找不到就说找不到"。单一向量检索容易漏掉专有名词、编号、精确短语；纯 BM25 又缺少语义泛化。引用准确率与拒答能力是本项目最核心的简历亮点。

## 决策

1. **召回**：Qdrant 中同时存 dense（bge-m3）与 sparse（中文 BM25）向量。
2. **融合**：两路各取 top-N（N 可配，默认 20），用 RRF（Reciprocal Rank Fusion）融合。
3. **重排**：对融合后的 top-20 用 `bge-reranker-v2-m3` 重排，取 top-5 作为上下文。
4. **拒答（两层）**：第一层是检索闸门，top1 rerank 分数低于 `retrieval_gate_rerank_score`（默认 0.01）时不调用生成模型，直接返回"资料中未找到"；第二层由生成 prompt 处理"话题相关但缺少具体事实"的灰区问题。单阈值无法同时满足召回与拒答，原因见 ADR-0009。
5. **引用**：每个进入上下文的 chunk 带稳定 ID、源文件、页码/段落；生成结果必须引用这些 ID，前端可点击定位。

## 备选与取舍

| 方案 | 取舍 |
| --- | --- |
| 纯向量检索 | 实现最简单；专有名词/编号/精确短语召回差，引用容易错。 |
| 纯 BM25 | 精确匹配强；同义表达与语义问题弱。 |
| **混合 + RRF + rerank（选择）** | 兼顾精确与语义；有明确的工程叙事与可调参数；代价是多一个 rerank 模型与延迟。 |
| Elasticsearch/OpenSearch 混合 | 成熟、可扩展；但对 1k～5k 单机规模过重，运维成本高。 |
| 不做 rerank | 省显存与延迟；引用准确率与"检索深度"亮点明显变弱。 |

## 阶段 0 验证发现：中文 BM25 不能用 FastEmbed

FastEmbed 的 `Qdrant/bm25` 分词器不具备中文分词能力。实测：

| 输入 | 产出 token 数 |
| --- | --- |
| `混合检索结合向量与关键词` | **1** |
| `hybrid retrieval combines dense and sparse` | 5 |

中文整句会退化成单个 `[UNK]` 项，BM25 的精确匹配优势在中文语料上完全失效。

因此稀疏向量改为**自建**：`jieba` 分词 → 去停用词与标点 → 词频作 value → CRC32 哈希为 uint32 index；写入 Qdrant 时开启 `Modifier.IDF`，由服务端按集合统计计算 IDF。既不引入额外模型或服务，也保留了"精确词命中"的能力。

代价：分词质量依赖 jieba 词典；哈希有极低碰撞概率；停用词表需自己维护。字符 bigram 作为备选未实测：语料规模小，jieba 词级已在混合检索中带来稳定增益，先不做额外切分对比。

## 阶段 2 实测（2026-10-25）

40 题评测集（`eval/stage2/questions.jsonl`）上的结果，完整数据见 `docs/eval/stage2-report.md` 与 ADR-0009：

| 模式 | Hit@5 | Recall@5 | MRR@5 | 总耗时 p50 |
| --- | --- | --- | --- | --- |
| 纯向量 | 93.3% | 82.8% | 0.776 | 22 ms |
| 混合（RRF, k=60, top_n=20） | 96.7% | 91.1% | 0.806 | 22 ms |
| 混合 + rerank（top_k=5） | 93.3% | 87.2% | 0.844 | 312 ms |

- 混合召回把 Recall@5 从 82.8% 提到 91.1%，验证了“稠密 + 稀疏互补”的假设；延迟增加约 3 ms。
- rerank 把 MRR 提到 0.844，但对“同义改写”类问题给分偏低，Recall@5 反而下降 3.9 个百分点。保留 rerank 的理由与备选方案（三路 RRF / Borda / 固定保留前 3）见 ADR-0009。
- rerank 额外延迟 p50 287 ms（20 个候选，CUDA）；检索总耗时 p50 312 ms、p95 334 ms。首 token p50 899 ms，rerank 未成为瓶颈。
- 端到端 10/10 无答案题拒答、0 误拒，其中 5 题由闸门拦截、5 题由生成层拦截。

## 后果

- 需要自建 30～50 题评测集，覆盖：精确术语、语义改写、跨文档综合、无答案。
- 指标：Recall@5、引用准确率、拒答正确率、首 token 延迟。
- 阈值不能拍脑袋：阶段 2 用评测集扫参，记录在验收文档与 ADR 更新中。
- rerank 与生成模型同时驻留可能超 8GB；降级顺序见 ADR-0002。
